# Hosted web licensing

Vietnamese owner instructions: [Hướng dẫn cấp license web](huong-dan-cap-license-web.md).

Accepted policy: a perpetual license activates one email account, usable on multiple devices. Socialchoice operates the hosted storage. SCW1 web licenses and machine-bound SC2 desktop licenses are different products. Starter, Professional and Business currently share features; no commercial feature limits or prices have been chosen.

## Runtime and isolation

The Cloudflare Worker keeps the existing `WORKSPACE` actor named `single-admin-workspace`. `CUSTOMER_DIRECTORY` stores encrypted accounts, license ownership, session hashes and recovery hashes. `CUSTOMER_WORKSPACES` creates an independent SQLite actor for each customer UUID. The gateway selects that UUID from a verified session and signs an internal context; request headers cannot select private customer data. Background runners verify the stored license before running. Existing provider permissions, publishing confirmations and uncertain-result safeguards still apply.

Customer cookies are HttpOnly, Secure, SameSite=Lax, with an eight-hour absolute lifetime. Multiple device sessions coexist. Sign-out revokes that device; recovery rotates the password and recovery code and revokes all previous central sessions. Requests already in flight may complete. Recovery codes are shown once after activation/recovery; there is no email password-reset delivery. Losing both password and recovery code has no implemented self-service recovery route. Account operations return their recovery code before workspace initialization; a failed initialization is retried on the next request.

Internal customer-context and license-authority messages retain their30second signed expiry. Future timestamp upper bounds permit up to5seconds of clock difference between actors; expiry itself has no grace. This prevents valid messages being rejected when the receiver observes an older I/O clock. HMAC, stored session matching,8hour absolute customer expiry and revocation checks remain enforced. Cloudflare documents [I/O-based timers](https://developers.cloudflare.com/workers/runtime-apis/performance/). See [session timing fix](../plans/reports/bugfix-261026-1442-customer-session-clock-report.md).

OAuth uses the existing shared provider App, customer session and OAuth nonce/state. Public media paths include the workspace UUID and require the existing expiring, asset-bound signed capability. Private media stays authenticated. Managed media storage supersedes the earlier desktop-only customer-storage decision for this web runtime. The local Node server remains owner-only; use the actual isolated Workers tests for customer development.

## Owner issuance

Primary route: owner signs in at `/admin/licenses`. Only an authenticated administrator session in the owner runtime can call `/api/admin/licenses/status|list|issue|download|revoke`. Customer workspace and unrestricted local mode are denied server-side. The form requires customer email, owner label, edition and explicit payment verification. It does not process payments. The server verifies its Ed25519 private key matches the existing public key before enabling issuance.

The owner explicitly approved hosted signing on2026-10-25. `SOCIALCHOICE_WEB_LICENSE_PRIVATE_KEY` is the base64 PKCS8 PEM in the existing Worker secret store; it is never a VITE variable, response field or browser upload. The encrypted local issuer remains a backup. Issuance history (including downloadable token) uses the owner's encrypted SqliteMap, not public entities. One request UUID returns the exact same signed file on retry; changed details under that UUID fail409. A new web request for an email already issued by the web service fails409; download the original file. The history shows100recent web-issued licenses; previous Windows-issued files are not synchronized. Edition upgrades remain unavailable.

### Customer activation tracking

Owner history is asynchronously enriched through the existing HMAC authority with a bounded batch of at most100license UUIDs. The directory returns only license ID, activation boolean, activation timestamp and latest successful sign-in timestamp. Customer/anonymous callers cannot access this history; passwords, recovery hashes, sessions and tokens are not returned. A directory lookup failure fails the list request rather than reporting customers as pending.

New registrations record `activated_at`; successful session creation records `last_login_at`, including registration/recovery. Failed or revoked login does not advance it. Existing accounts retain null historical timestamps until a new sign-in; activation remains derived from central ownership. Owner search matches email/customer label case-insensitively and combines license/activation filters within the100recent issued records. Explicit refresh retrieves current metadata. The result-file download rechecks server entitlement; issuing a license refreshes authoritative history. The owning page uses stacked existing panels so the expanded history can use the canvas width. No global design tokens changed.

### Revocation

Owner may revoke a listed web license through an explicit confirmation. `/api/admin/licenses/revoke` retains the existing owner-only authentication and CSRF boundary. The central encrypted directory registry commits denial first, invalidating every matching activated-account session and blocking registration, login and recovery. The owner record then stores the original revocation timestamp; retries reconcile safely if local history persistence fails after central denial. Revoked files cannot be downloaded or returned through issuance retry. Records/content/provider credentials stay stored; no customer data is deleted and no refund/restore action is implied.

Backend-only authority requests use a short-lived, domain-separated HMAC over the exact operation/input via the existing CUSTOMER_DIRECTORY binding. The public Worker cannot route `/internal/license-authority`. Customer private/public-media requests and alarms check the stored license centrally. Delivery graph calls, including TikTok refresh, check again before each provider call. Temporary authority/network/configuration failure blocks calls with503; definitive revocation blocks403 and removes the revoked workspace alarm. Requests already submitted to a provider may finish; revocation does not undo published content. An entitlement rejection before TikTok refresh restores the unconsumed local refresh claim without treating it as a lost rotating response.

Revocation is enforced by the hosted service; the signed SCW1 file remains cryptographically signed. Removing the revocation registry, running older code that does not consult it, or losing its persistent storage can undo enforcement. Preserve the central registry on backups/rollbacks and deploy compatible enforcement code. Each customer request/provider call adds a central status check; do not assume license caching or unlimited free hosting. There is no restore UI or arbitrary Windows-license import/revocation interface in this change.

The following Windows tool remains available as an alternative:

On Windows run `pnpm run license:web:owner` from the project. Choose setup once, then issue for each verified purchase. The wrapper `scripts/web-license-owner.ps1` defaults to `D:\Socialchoice-Private\web-issuer`, outside source. It restricts the key directory to the current Windows user, creates an encrypted private key and protects its random passphrase with current-user DPAPI. It refuses to replace an existing issuer or license file. Never initialize a Windows production issuer through the direct Node command: POSIX file modes do not establish a Windows DACL.

Use `-Action Init -KeyDirectory <new-outside-directory>` or `-Action Issue -Email <email> -Licensee <label> -Edition starter|professional|business -OutputPath <new-file.scweblicense> -PurchaseConfirmed` for explicit noninteractive operation. The menu asks for purchase confirmation; this is an operator decision, not payment verification. No private key or passphrase is printed. DPAPI files require the original Windows profile; copying them to a different computer is not a portable backup. Maintain a full recoverable system/profile backup before relying on the issuer commercially. Do not delete that profile or rotate the issuer to fix a lost backup.

The low-level Node issuer remains available for tooling using an explicitly protected key directory and privately supplied `SOCIALCHOICE_ISSUER_PASSPHRASE`; it does not configure Windows access controls. Never put the passphrase in chat, arguments, source or logs. The Windows wrapper restores the previous transient environment value after each call.

Send the license file privately to its purchaser. The customer enters its exact email, a password of 15–256 characters and the license at activation. The server checks issuer signature, exact web product, email and unique license ownership. A second account cannot reuse that license. The private signing key is allowed only in the explicitly approved backend secret store and protected owner backup; never in Vercel frontend artifacts or on a customer device.

## Release gate

1. Owner creates and backs up the encrypted production issuer privately. Configure its public hex key as `SOCIALCHOICE_WEB_LICENSE_PUBLIC_KEY` on the existing Worker. Preserve storage and provider encryption keys; replacing those keys can lose access to encrypted state. Changing issuer public keys invalidates existing licenses; issuer rotation is not implemented. Listed web-issued licenses can be revoked through the owner interface described above.
2. Review the current public privacy/terms pages for managed customer storage before customer launch. Finish provider App review and actual grant testing separately. Existing Meta test returned no eligible Pages; commercial connection readiness is not established.
3. Run `pnpm test`, `pnpm run typecheck`, `pnpm run lint`, `pnpm run build`. Deploy the existing named Worker with the appended SQLite migration, then the matching Vercel frontend. Preserve all existing bindings and actor identities. Never delete customer namespaces during rollback.
4. Verify customer config, owner access, two isolated licensed accounts, OAuth callback routing, recovery and signed media on the actual HTTPS deployment. No live post is implied by activation testing. Keep activation closed until these pass. Hosting usage and data retention remain operational responsibilities; perpetual purchase does not make hosting free or unlimited.
