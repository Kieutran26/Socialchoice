# Evergreen / recurring posts

In the web app, open **All Posts → a post → Evergreen / recurring post**. Use a live draft or successfully published post with connected destinations. Choose every 2 weeks or every month, first date/time and timezone. Optionally set an inclusive local end date and total successful publication count (0 means unlimited). Review the exact captions/accounts/media and upcoming dates, check the approval box, then enable automatic recurrence. This is separate approval from a one-off post or calendar plan.

Review alone creates no draft, job or publishing attempt. Confirmation atomically creates a separate scheduled occurrence for the selected accounts. Each occurrence appears in normal All Posts/calendar/history and uses the existing durable publishing pipeline. The source post stays unchanged. Shared/platform/account captions, media, TikTok options and follow-up comments are retained; old per-account one-off times are cleared so recurring destinations use the approved common time.

Monthly schedules keep the original day; January 31 becomes February 28/29 and then March 31. Fortnights add 14 local calendar days, preserving local wall time across daylight-saving changes. A nonexistent daylight-saving time pauses/rejects the schedule for review. Date/time inputs use minute precision. First publication must be between one minute and one year away.

Only after every destination confirms publication does the next occurrence get created. A failed, unknown, cancelled or partially failed occurrence pauses the series; it is not retried or duplicated automatically. Use normal history to inspect it before approving a new series. Delayed completion skips expired periods and creates only one future occurrence, never a catch-up burst. The existing 15-minute missed-delivery window also applies; an occurrence missed by more than that pauses for review. Skipped periods do not consume the successful-publication limit. End date can finish a series before the count is reached.

Source content/media/account identity or authorization changes pause the series and cancel queued destinations before delivery. A fresh review is required. Routine account sync timestamps are not identity changes. Provider permissions/token expiry are still checked by the existing adapters. Future TikTok occurrences keep frozen consent/options, while the delivery adapter fetches fresh creator limits before sending; normal first reviews still require current creator settings. Platform availability/visibility/content restrictions continue to apply.

**Pause recurrence** cancels unstarted destinations. **Stop recurrence** ends the series. Already started deliveries cannot be recalled. Re-enable through a fresh review, starting a new series with a new count/history; paused/stopped series cannot be silently reactivated by replaying an old confirmation. Review confirmations expire after 10 minutes. Original and generated publication history remains available.

Deleting a source with an active series is blocked. Pause or stop it first; normal publishing-history protections still apply.

Series records are private to each workspace in SQLite and are unavailable through generic entity writes. Authenticated POST `/api/recurring/{prepare,confirm,list,pause,stop}` uses one input object in `args` and the standard JSON/application-header/origin/session boundary. Prepared policy, fingerprints and consent are server-owned. Repeated confirmation cannot duplicate the first occurrence. Future progress and occurrence approval commit together, with existing per-destination delivery claims preventing resend after an ambiguous network result.

The local Node publishing server must remain running. Hosted Cloudflare workspaces use existing Durable Object alarms and license checks; the browser can be closed. Startup resumes pending work. This feature does not install a new cron, require Docker, deploy the app, or publish test content to real accounts. Frontend/backend updates must be deployed together before online use.

Verification: `node --test server/recurring-posts.test.js server/facebook-scheduled-delivery.test.js server/facebook-multi-page.test.js server/tiktok.test.js` plus normal project test/typecheck/lint/build.
