# Facebook Pages connection

Implemented connection code: server OAuth code exchange, long-lived user-token exchange, Page discovery, selected Page import, encrypted Page tokens, reconnect, Page-access check and local disconnect. The app requests `pages_show_list` and `pages_read_engagement`; publishing permissions and delivery remain a later step. No real connection is claimed until the owner completes a real Meta flow. No test Pages or fake tokens are inserted by runtime.

## Owner setup

Recommended on Windows: run `npm run setup:meta`. Enter App ID, the supported Graph API version, callback URI and optional Login configuration ID; enter App Secret in the hidden prompt. This creates ignored `.env.meta` and generates the encryption key automatically. It refuses to overwrite an existing configuration/key and prints no secret. `npm start` and `npm run dev:api` load this file after `.env.local`. Preserve/restrict/back up it privately; edit it locally for later App changes while keeping the encryption key. No credential has been supplied through chat or generated for a real Meta account by the assistant. The manual alternative below is for owners managing environment files themselves.

1. In [Meta for Developers](https://developers.facebook.com/apps/), create/configure your app with a Facebook Login flow eligible for Pages access. Use an account authorized to administer the test Page. Configure permissions/access in the app dashboard. App roles, App Review, Advanced Access and business verification may affect who can authorize the app. Creating an app does not automatically grant those approvals.
2. Register the exact callback as a Valid OAuth Redirect URI. For the one-process local app: `http://127.0.0.1:3001/api/meta/callback`. If Meta refuses HTTP/loopback for your app's mode, use a properly configured HTTPS deployment and register its exact callback. Do not expose unauthenticated local development through a tunnel. For Vite development use the frontend origin/port in the callback, since browser cookies belong to that origin.
3. Set server-only values in `.env.local`: `META_APP_ID`, `META_APP_SECRET`, `META_GRAPH_VERSION` (supported version from your app dashboard), `META_REDIRECT_URI`, `META_TOKEN_ENCRYPTION_KEY`. If your Facebook Login for Business setup requires a configuration ID, also set `META_LOGIN_CONFIG_ID`. Do not put any secrets in `VITE_*`, frontend fields, Git or chat. `ready` only means local configuration is valid, not Meta approval or API access.
4. Generate the encryption key once on your machine. This command places it in a separate ignored file for local transfer into `.env.local`, without printing it: `node --input-type=module -e "import {randomBytes} from 'node:crypto'; import {writeFileSync} from 'node:fs'; writeFileSync('.env.meta-key', 'META_TOKEN_ENCRYPTION_KEY='+randomBytes(32).toString('hex')+'\n', {flag:'wx',mode:0o600})"`. Copy that line locally into `.env.local`. Keep a private backup of the key, restrict Windows file permissions and do not regenerate it while stored connections exist. Loss/change of the key requires reconnection. Never send the key here.
5. Ensure the Socialchoice admin password has been set with `npm run setup:admin`. Rebuild (`npm run build`) and restart your existing app (`npm start`), or restart the development API/frontend pair. Stop/restart your current server rather than starting duplicates.
6. Sign in, create a real active brand, then open Social Accounts → choose brand → Connect / reconnect Facebook. Sign in only on Facebook's official domain. Grant the allowed Page permissions. On return, choose the Pages actually returned by Meta and click Connect selected Pages. Select within ten minutes; restart/expiry requires starting OAuth again.

Keep browser hosts consistent: do not alternate `localhost` and `127.0.0.1`. The callback origin must match the app origin you use in the browser. For public HTTPS, it must match `SOCIALCHOICE_PUBLIC_ORIGIN` and the reverse proxy's preserved Host. No public server/domain has been created by this work.

## Behavior and safety

- No Facebook password is collected by Socialchoice. OAuth code exchange happens on the server. A random single-use ten-minute state and separate HttpOnly SameSite=Lax flow cookie are bound to an active admin session. This permits the external callback while keeping the admin cookie SameSite=Strict.
- Page tokens remain in a private SQLite table as AES-256-GCM ciphertext with record-bound authentication. Generic entity APIs cannot read that table or assign connected/credential metadata. Page names, IDs, granted scope names and an opaque credential ID are safe metadata; no token goes to the browser.
- Unselected Page tokens stay only in temporary server memory until selection expiry/import/restart. The user token is used to discover Pages and is not persisted. Each imported Page stores its own token. Reconnect repeats Meta authorization and updates the selected Page's credential for the same brand/ID; multiple authorized Facebook profiles can be connected in successive flows. Facebook may reuse its active browser profile; switch profiles on Facebook itself, not by entering another profile's password in this app.
- Check Facebook access makes a real Page identity request. `connected` records a successful authorization/import or last successful access check, not a promise that the token is still valid or can publish. Known authorization failure marks it expired; transport failures do not fabricate expiry. Reconnect handles token expiry/revocation. There is no background refresh or platform deauthorization webhook yet.
- Disconnect deletes the local credential and keeps the destination/history. It does not revoke all permissions for the Facebook profile, which could affect other connected Pages. To remove the app's authorization at Meta, use Facebook's app/business integration settings; then check/reconnect affected Pages locally. Deletion requires disconnect first and continues to preserve publishing history.
- Page connection does not enable Publish Now, automatic delivery, metrics or claim any published result. Those controls remain unavailable.

## Evidence and limitations

Meta's [official Page-token collection](https://www.postman.com/meta/facebook/request/bqfxwbp/get-access-tokens-of-pages-you-manage) documents `me/accounts`, Page tokens and task metadata. Direct [manual-login docs](https://developers.facebook.com/docs/facebook-login/guides/advanced/manual-flow/) and [Pages getting started](https://developers.facebook.com/docs/pages-api/getting-started/) returned HTTP 429 during research. Network API success, exchange behavior and app-specific permission eligibility require real owner verification; do not treat local tests as Meta integration certification.

If authorization fails: verify exact callback/app mode/version/roles/permissions in Meta; denied Page permission or no accessible Pages is shown clearly. Remote response bodies/token values are never echoed to the client. Live testing must be done with owner-provided local configuration and a permitted Page. No paid connector is needed, but hosting and platform approval requirements remain external.
